## 2. Before / After Request & Response Contracts

- **Runtime Load (`POST /api/nexus.runtime-load` → `POST /v1/runtime/load`)**
  - **Before:** Client sent `{ model_id }`; Host rejected because `body.model` was missing. Gateway ran synchronously without returning `operation_id`.
  - **After:** Client sends `{ model: "<canonical_id>", kind: "chat", async: true }`. Host validates `model`, forwards `{ model, kind, async }`, preserves HTTP status codes, normalizes FastAPI `{ detail }` errors, and redacts credentials. Gateway validates model compatibility before touching the worker, deduplicates concurrent loads for the same `(kind, model)`, and returns `202 { status: "loading", operation_id, model, kind, worker }` (or `200 { status: "loaded", ... }` if already active).
- **Progress (`GET /api/nexus.runtime-progress?operation_id=<id>` → `GET /v1/progress/{id}`)**
  - **Before:** Host only proxied `/v1/progress`; Client read flat `status`/`stage`/`percent`.
  - **After:** Host forwards `?operation_id=...` (regex-validated) to `/v1/progress/{operation_id}` and `/v1/progress` otherwise. Client polls with overlap guard (`pollInFlightRef`) and `AbortController` cleanup, displaying real byte progress during staging and an indeterminate indicator during weight loading/placement/generation (never fabricating percentages).
- **Runtime & GPU Memory (`GET /api/nexus.runtime` → `GET /v1/runtime`)**
  - **Before:** Client read `loaded_model_id` and `vram_allocated_mb`.
  - **After:** Client reads `worker.alive`, `worker.active_model_id`, `worker.cuda_allocated_bytes`, and `hardware.{cuda_available, total_vram_bytes, free_vram_bytes, gpus}` so Ready status is strictly confirmed by the live worker.
- **Image Model Selection (`GET /api/nexus.image-models`, `POST /api/nexus.image-model`)**
  - **Before:** Client sent `{ model_id }` and expected `selected_image_model`; Host expected `{ modelId }` and omitted `models` on `POST`.
  - **After:** Both layers use `{ modelId }` on `POST` and `{ selectedModelId, models, qualityProfiles }` on both `GET` and `POST`.

## 3. Worker Loading & Progress Data Flow

`ModelDirectoryResolver` (`provider` + canonical `modelId` + catalog `displayName`) → `NexusRuntimeControl` (`Load Qwen3-VL 8B`) → `POST /api/nexus.runtime-load` (`{ model, kind: 'chat', async: true }`) → Host auth/validation/redaction → `POST /v1/runtime/load` → catalog & compatibility pre-check → deduplicated `operation_id` → serialized background `res_mgr.acquire(...)` → `resolving` → `checkpoint_validation` / `staging` (real bytes) → `processor_init` / `weight_loading` (indeterminate) → `placement` → live `worker_mgr.status()` verification (`alive && active_model_id == model_id`) → `ready` → Client polls `/api/nexus.runtime-progress?operation_id=...` + `/api/nexus.runtime` and transitions badge from `Loading · Qwen3-VL 8B` → `Ready · Qwen3-VL 8B`.
